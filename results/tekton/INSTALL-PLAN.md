# Tekton Pipeline — Installation Plan

## Project Overview

**Tekton** is a CNCF-graduated CI/CD framework for Kubernetes. It provides Kubernetes-native CRDs (Task, TaskRun, Pipeline, PipelineRun) and controllers that execute CI/CD workloads as Pods. The controller and webhook processes are instrumented with OpenTelemetry and expose Prometheus metrics natively.

---

## 1. Installation Method

| Field | Value |
|---|---|
| Method | `kubectl apply` — official release manifest |
| Version | **v1.12.0** (released 2026-05-04) |
| Manifest URL | `https://github.com/tektoncd/pipeline/releases/download/v1.12.0/release.yaml` |
| Primary namespace | `tekton-pipelines` |
| Resolvers namespace | `tekton-pipelines-resolvers` |

No Helm chart exists for the core Tekton Pipelines component. The upstream project publishes a single `release.yaml` that installs all CRDs, RBAC, and controllers.

## 2. Telemetry Configuration

### 2a. Traces — OTLP HTTP (native)

Tekton supports OTLP trace export via two ConfigMaps:

**`config-tracing` in `tekton-pipelines`** (legacy, still works in v1.12.0):
```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: config-tracing
  namespace: tekton-pipelines
data:
  enabled: "true"
  endpoint: "http://otel-collector-opentelemetry-collector.opentelemetry.svc.cluster.local:4318/v1/traces"
```

**`config-observability` in `tekton-pipelines`** (new in v1.12.0):
```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: config-observability
  namespace: tekton-pipelines
data:
  metrics-protocol: prometheus
  tracing-protocol: "http/protobuf"
  tracing-endpoint: "http://otel-collector-opentelemetry-collector.opentelemetry.svc.cluster.local:4318/v1/traces"
  tracing-sampling-rate: "1.0"
```

Both ConfigMaps will be patched after the base manifest is applied.

### 2b. Metrics — Prometheus scrape (native)

Tekton exposes Prometheus metrics on port `9090` (`/metrics`) from four services:

| Service | Namespace | Port |
|---|---|---|
| `tekton-pipelines-controller` | `tekton-pipelines` | 9090 |
| `tekton-pipelines-webhook` | `tekton-pipelines` | 9090 |
| `tekton-events-controller` | `tekton-pipelines` | 9090 |
| `tekton-pipelines-remote-resolvers` | `tekton-pipelines-resolvers` | 9090 |

Key Tekton metric families:
- `tekton_taskrun_duration_seconds` — histogram of TaskRun durations
- `tekton_taskrun_count` — counter of TaskRuns by status
- `tekton_pipelinerun_duration_seconds` — histogram of PipelineRun durations
- `tekton_pipelinerun_count` — counter of PipelineRuns by status
- `tekton_running_taskruns_count` — gauge of active TaskRuns
- `tekton_running_pipelineruns_count` — gauge of active PipelineRuns
- Standard controller-runtime workqueue/reconciler metrics

### 2c. Logs — stdout only

Tekton uses structured JSON logging (zap) to stdout. No OTLP log export is supported. Logs are available via `kubectl logs` but not collected into the OTLP pipeline.

## 3. Collector Changes

The OTel Collector's Prometheus receiver needs new scrape targets for all four Tekton services. The updated `collector/values.yaml` adds:

```yaml
receivers:
  prometheus:
    config:
      scrape_configs:
      - job_name: tekton-pipelines-controller
        scrape_interval: 15s
        static_configs:
        - targets:
          - tekton-pipelines-controller.tekton-pipelines.svc.cluster.local:9090
      - job_name: tekton-pipelines-webhook
        scrape_interval: 15s
        static_configs:
        - targets:
          - tekton-pipelines-webhook.tekton-pipelines.svc.cluster.local:9090
      - job_name: tekton-events-controller
        scrape_interval: 15s
        static_configs:
        - targets:
          - tekton-events-controller.tekton-pipelines.svc.cluster.local:9090
      - job_name: tekton-pipelines-remote-resolvers
        scrape_interval: 15s
        static_configs:
        - targets:
          - tekton-pipelines-remote-resolvers.tekton-pipelines-resolvers.svc.cluster.local:9090
```

The `prometheus` receiver is added to the `metrics` pipeline alongside the existing `otlp` and `k8s_cluster` receivers.

## 4. Routing / Ingress Setup

Tekton does not require ingress or routing configuration for telemetry evaluation. It is a controller-only component — all work happens inside the cluster when TaskRuns/PipelineRuns are created. No external HTTP traffic routing is needed.

## 5. Traffic Generation

Traffic is generated by creating Kubernetes resources (TaskRuns and PipelineRuns) that exercise the Tekton controller reconciliation loop.

### Step 1 — Simple TaskRun (exercises controller + spans)
```yaml
apiVersion: tekton.dev/v1
kind: TaskRun
metadata:
  name: hello-world
  namespace: default
spec:
  taskSpec:
    steps:
    - name: echo
      image: alpine:3.19
      script: |
        echo "Hello from Tekton!"
        sleep 2
```

### Step 2 — PipelineRun with multiple Tasks (exercises pipeline-level spans + metrics)
```yaml
apiVersion: tekton.dev/v1
kind: Pipeline
metadata:
  name: demo-pipeline
  namespace: default
spec:
  tasks:
  - name: task-a
    taskSpec:
      steps:
      - name: step-a
        image: alpine:3.19
        script: echo "Task A"
  - name: task-b
    runAfter: [task-a]
    taskSpec:
      steps:
      - name: step-b
        image: alpine:3.19
        script: echo "Task B"
  - name: task-c
    runAfter: [task-a]
    taskSpec:
      steps:
      - name: step-c
        image: alpine:3.19
        script: echo "Task C"
---
apiVersion: tekton.dev/v1
kind: PipelineRun
metadata:
  name: demo-pipeline-run
  namespace: default
spec:
  pipelineRef:
    name: demo-pipeline
```

### Step 3 — Multiple runs for metric accumulation
Run 5–10 TaskRuns to populate histogram buckets and counters.

## 6. Installation Steps Summary

1. **Apply Tekton v1.12.0 manifest**
   ```bash
   kubectl apply --context kind-otel-eval-tekton \
     -f https://github.com/tektoncd/pipeline/releases/download/v1.12.0/release.yaml
   ```

2. **Wait for controllers to be ready**
   ```bash
   kubectl rollout status deploy/tekton-pipelines-controller \
     -n tekton-pipelines --context kind-otel-eval-tekton --timeout=3m
   ```

3. **Patch `config-tracing` to enable OTLP trace export**
   ```bash
   kubectl patch configmap config-tracing \
     -n tekton-pipelines --context kind-otel-eval-tekton \
     --type merge -p '{"data":{"enabled":"true","endpoint":"http://otel-collector-opentelemetry-collector.opentelemetry.svc.cluster.local:4318/v1/traces"}}'
   ```

4. **Patch `config-observability` to enable OTLP tracing (v1.12.0 path)**
   ```bash
   kubectl patch configmap config-observability \
     -n tekton-pipelines --context kind-otel-eval-tekton \
     --type merge -p '{"data":{"tracing-protocol":"http/protobuf","tracing-endpoint":"http://otel-collector-opentelemetry-collector.opentelemetry.svc.cluster.local:4318/v1/traces","tracing-sampling-rate":"1.0"}}'
   ```

5. **Upgrade OTel Collector with Prometheus scrape targets**
   ```bash
   helm upgrade otel-collector open-telemetry/opentelemetry-collector \
     --namespace opentelemetry \
     --kube-context kind-otel-eval-tekton \
     -f .otel-eval/tekton/collector/values.yaml \
     --wait
   ```

6. **Apply traffic generation manifests**
   ```bash
   kubectl apply --context kind-otel-eval-tekton \
     -f .otel-eval/tekton/tekton/routing/
   ```

7. **Wait for TaskRuns/PipelineRuns to complete and telemetry to flush**
   ```bash
   sleep 30
   ```

8. **Verify telemetry files**
   ```bash
   wc -l /tmp/otel-eval-tekton/traces.jsonl
   wc -l /tmp/otel-eval-tekton/metrics.jsonl
   ```

## Expected Telemetry Outcome

| Signal | Expected | Protocol | Source |
|---|---|---|---|
| Traces | Yes | OTLP HTTP (`/v1/traces`) | Tekton controller (in-process OTel SDK) |
| Metrics | Yes | Prometheus scrape | Tekton controller/webhook/resolvers `:9090/metrics` |
| Logs | No (stdout only) | N/A | Not collected into OTLP pipeline |

Spans expected per TaskRun:
- Root span: `reconcile` (controller reconcile loop)
- Child spans: step execution spans per Task step

Metrics expected:
- `tekton_taskrun_duration_seconds`
- `tekton_taskrun_count`
- `tekton_pipelinerun_duration_seconds`
- `tekton_pipelinerun_count`
- `tekton_running_taskruns_count`
- `tekton_running_pipelineruns_count`
- Controller-runtime workqueue metrics
